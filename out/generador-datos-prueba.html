Generador de Datos de Prueba en Español

Campos

Para probar un formulario, llenar una base de datos de desarrollo o hacer la demo de una aplicación necesitas datos que parezcan reales, pero sin usar información de personas reales. Este generador crea hasta 1,000 registros ficticios en español con nombres, apellidos, correos, teléfonos, direcciones, fechas de nacimiento, empresas y más. Los formatos corresponden a México, España, Colombia o Argentina, y puedes exportarlos a JSON, CSV o sentencias SQL INSERT.

Cómo usar

  1. 1

    Elige el país para adaptar teléfonos, ciudades y códigos postales

  2. 2

    Selecciona los campos que necesitas y el número de registros (hasta 1,000)

  3. 3

    Elige el formato de salida: JSON, CSV o SQL; en SQL, escribe el nombre de la tabla

  4. 4

    Pulsa «Generar datos de prueba» y copia o descarga el resultado

Beneficios

  • Nombres y apellidos hispanos frecuentes
  • Teléfonos, ciudades y códigos postales con formato de cada país
  • Correos con dominios reservados para pruebas
  • Edad coherente con la fecha de nacimiento
  • Exporta a JSON, CSV o SQL INSERT
  • Aleatoriedad criptográfica y sin enviar datos a servidores

Por qué usar datos ficticios

Copiar datos de clientes reales a un entorno de desarrollo o de pruebas es un riesgo de seguridad y, en muchos países, una infracción a las leyes de protección de datos personales, como la ley federal mexicana en la materia o el Reglamento General de Protección de Datos en España. Los datos ficticios permiten probar validaciones, diseños y rendimiento sin exponer a nadie. Además, puedes generar tantos como necesites para probar paginaciones, búsquedas o reportes con volumen.

Datos con formato local

Los generadores en inglés producen nombres como «John Smith» y teléfonos de Estados Unidos, que no sirven para probar un sistema hispano. Este generador usa nombres y apellidos frecuentes en países de habla hispana, dos apellidos en México, España y Colombia, y formatos locales. Por ejemplo, teléfonos de 10 dígitos con +52 para México, móviles que empiezan con 6 para España, celulares con 3 para Colombia y el 9 de celular argentino. Las ciudades vienen con su estado o provincia y un código postal con el prefijo de la zona.

Correos que nunca llegan a nadie

Los correos generados usan dominios reservados para documentación y pruebas, como example.com, example.org o los terminados en .test, definidos en el RFC 2606. Así, si tu aplicación envía correos por error durante una prueba, no llegarán a ninguna persona real. Es una práctica recomendada para cualquier entorno de desarrollo.

Exportar a JSON, CSV o SQL

El formato JSON sirve para mocks de APIs y pruebas de front-end. El CSV se abre en Excel o se importa en la mayoría de las herramientas de datos; se descarga con codificación UTF-8 compatible con Excel. El formato SQL genera una sentencia INSERT por registro, con las comillas escapadas, lista para ejecutarse en MySQL, PostgreSQL o SQLite después de crear la tabla con las columnas elegidas.

Preguntas frecuentes

No. Se combinan al azar nombres, apellidos y direcciones de listas genéricas. Cualquier coincidencia con una persona real es casual.
