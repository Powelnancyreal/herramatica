Decodificador de JWT

Actualizado el 25 de octubre de 2026 · Ver fuentes

Pega un JSON Web Token y lee su header y su payload decodificados, con las fechas exp, iat y nbf traducidas a hora local y un aviso si ya expiró. Si el token usa HS256, HS384 o HS512, también puedes verificar su firma con la clave secreta.

El token se decodifica en tu navegador: no se envía a ningún servidor.

¿Qué significan los claims estándar que aparecen en el payload?

iss
Emisor: quién creó el token, normalmente la URL del servidor de autenticación.
sub
Sujeto: el identificador del usuario al que pertenece.
aud
Audiencia: la aplicación o API para la que es válido.
exp
Fecha de expiración, en segundos desde el 1 de enero de 1970 (UTC).
iat
Momento en que se emitió el token.
nbf
El token no es válido antes de esta fecha.
jti
Identificador único del token, útil para revocarlo.

¿Qué revisar cuando una API rechaza tu token?

  • ✓Que exp no haya pasado y que nbf no sea una fecha futura.
  • ✓Que aud coincida con la API a la que llamas.
  • ✓Que el reloj del servidor no esté desfasado unos minutos.
  • ✓Que el encabezado sea Authorization: Bearer seguido del token, sin comillas ni espacios extra.
  • ✓Que no se haya cortado al copiarlo: debe tener exactamente dos puntos.

Un token de producción es una credencial: quien lo tenga puede actuar como tú hasta que expire. La decodificación ocurre en tu navegador, pero evita compartir tokens en capturas o chats.

¿Qué otras herramientas sirven para depurar autenticación?

El codificador Base64 para decodificar partes sueltas, el formateador JSON para revisar el payload y el generador de hash para comprobar resúmenes SHA-256.
